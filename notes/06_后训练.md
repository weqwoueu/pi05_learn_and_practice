# 06 冻结与梯度排查

需要查函数或类时，打开 [API 速查](Torch与Python_API速查.md)，按顶部题号表阅读。可以看着 API 写第一遍。

实现：[ex06_finetune.py](../exercises/ex06_finetune.py)。检查：`uv run python run.py 06`。建议 35—50 分钟。

## 场景

给定 adapter → backbone → head 的小模型，adapter 和 head 要训练，backbone 参数冻结。注意 adapter **在冻结主干之前**，所以梯度仍需经过 backbone 的计算传回 adapter。

实现：

1. freeze_backbone：仅冻结 backbone 参数，并清理它已有的 grad。adapter/head 保持可训练。
2. train_step：切换 train、清上一步梯度、前向、MSE、backward、按 max_grad_norm 裁剪、optimizer.step；返回 Python float loss。不在函数里重新创建优化器。
3. gradient_report：返回 参数名→bool。仅当 grad 存在、全部有限且至少一个元素非零时为 True；None、全零、含 NaN/Inf 均为 False。

测试会比较连续两个 step，检查梯度累积、裁剪、参数更新及上游 adapter 梯度。

## 分层提示

<details><summary>提示一：冻结不等于不记录计算</summary>

requires_grad=False 作用于参数；no_grad/detach 可能切断整段计算图。检查 adapter 是否仍有梯度。

model.eval() 也不是冻结，它控制 dropout、BatchNorm 等模块的行为。
</details>

<details><summary>提示二：训练步骤顺序</summary>

裁剪发生在 backward 之后、step 之前。zero_grad 应在本轮 backward 前执行。

判断“冻结成功”要比较前后参数；判断“可训练模块接通”要检查梯度和参数变化，两者都不能只看 loss。
</details>
