# 01 关节状态如何进入 π0.5

需要查函数或类时，打开 [API 速查](Torch与Python_API速查.md)，按顶部题号表阅读。可以看着 API 写第一遍。

实现：[ex01_state.py](../exercises/ex01_state.py)。检查：`uv run python run.py 01`。建议 35—45 分钟。

## 先把路径说清楚

你本地默认 π0.5 路径是：

```text
机器人状态 → 数据变换 → 按训练统计量归一化 → 每维状态分桶
→ 写成 State: 0 128 ... 文本 → SentencePiece 分词
→ token ID → embedding → 与图像 token 构成 prefix
```

**桶编号不是词表 ID。** “128”写进文本后还会被分词，不能假设一维关节恰好对应一个语言 token。

π0 的分支另外通过 state_proj 把连续状态变成后缀 token；不要把这条路径直接套到默认 π0.5。

## 接口与精确要求

1. `normalize_quantile`：y = 2(x−q01)/(q99−q01+eps)−1，eps 默认 1e-6，支持 NumPy 广播，**不 clip**。实现对应逆变换。
2. `discretize_state`：匹配仓库的 `np.digitize(state, np.linspace(-1,1,bins+1)[:-1])-1`，默认 256 桶。−1→0，0→128，1→255；低于−1→−1，高于1→255。这是现有代码的实际边界行为。
3. `build_prompt`：task 先 strip，再将下划线、换行替为空格；状态整数用单空格连接。格式为：
   `Task: insert, State: 0 128 255;\nAction: `
   若有 advantage，则在 State 后加 `, Advantage: positive`。注意真实字符串中的换行和结尾空格。
4. `encode_prompt`：调用传入的 encode 回调，模拟真实分词器接口；BOS 由回调负责。输出 int64 IDs[L]、bool mask[L]。右侧补 0，超长右截断，L≤0 报错。mask 由实际长度决定；回调返回的有效 0 也应保留为 True。

本题不下载 tokenizer，重点是接通路径、明确边界。

## 分层提示

<details><summary>提示一：不要跨过文本分词</summary>

把“归一化值→桶编号”“桶编号→字符串”“字符串→分词器→ID”分开实现。先构造完整 prompt，再让 encode 处理它。

读取实际长度后，取 min(实际长度,max_length)；用这个长度创建 mask。
</details>

<details><summary>提示二：反归一化与顺序</summary>

反归一化先把 y 从 [-1,1] 变回相对比例，再乘带同一个 eps 的跨度，最后加 q01。

本地 ModelTransformFactory 的顺序是 TokenizePrompt 在 PadStatesAndActions **之前**。所以不要说“先补 32 维再将 32 个状态写成文本”。先检查你的机器人适配器实际提供了几维。
</details>
