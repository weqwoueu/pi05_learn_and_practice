# π0.5 代码细读与四天安排

目标：四天后能把一条 observation 从输入讲到输出动作，能写出核心模块，并能定位 mask、时间方向和梯度问题。每天按 5—6 小时安排；不把“读过文件”算作完成，要能画形状、复述与重写。

本次以当前本地仓库为准：PiStar 主线 HEAD 为 85e6951。基础模型可用 PyTorch 代码理解；项目中的 PiStar/RTC 改动需要回到对应 JAX 代码或历史提交确认。两套实现不能默认完全同步。

## 第一天：输入路径 + Attention

约 2 小时代码、2.5 小时练习、半小时复述。

读的顺序：

1. [piper_policy.py](../../openpi/src/openpi/policies/piper_policy.py)：Piper 输入字段、关节与夹爪排列、图像键和掩码。
2. [data_loader.py](../../openpi/src/openpi/training/data_loader.py) 的 transform_dataset，与 [training/config.py](../../openpi/src/openpi/training/config.py) 的 ModelTransformFactory：数据适配、归一化、模型变换的顺序。
3. [transforms.py](../../openpi/src/openpi/transforms.py) 的 Normalize、TokenizePrompt、PadStatesAndActions。
4. [tokenizer.py](../../openpi/src/openpi/models/tokenizer.py) 的 PaligemmaTokenizer.tokenize。
5. [pi0_config.py](../../openpi/src/openpi/models/pi0_config.py)：pi05、discrete_state_input、action_dim、action_horizon；再读 [pi0_pytorch.py](../../openpi/src/openpi/models_pytorch/pi0_pytorch.py) 的 embed_prefix、embed_suffix。

做 00、01、02。今天至少完成 Attention 的基本前向；全遮挡边界卡住可记录后第二天补齐。

必须产出一张手画图：

```text
原始机器人状态
  → 机器人数据变换
  → Normalize（训练集统计量）
  → 分桶 → State文本 → tokenizer IDs → 语言embedding
                                          ↓
多相机图像 → 视觉编码与投影 → 图像token → prefix
```

同时画动作路径：动作预处理/归一化/补维 → 训练时加噪 → action_in_proj → suffix。

验收：不看代码讲清“我的关节状态到底在哪里进入模型”。说出 π0.5 状态文本路径与 π0 state_proj 分支、分桶与分词的区别；能判断 TokenizePrompt 和 PadStatesAndActions 的先后。

## 第二天：Transformer 内部 + Flow Matching

约 2 小时代码、2.5 小时练习、半小时复述。

1. [gemma.py](../../openpi/src/openpi/models/gemma.py)：RMSNorm、Attention、FeedForward、Block。先跟 QKV、残差和 norm，不被 JAX 装饰器/分片设置打断主线。
2. 你当前打开的 [gemma_pytorch.py](../../openpi/src/openpi/models_pytorch/gemma_pytorch.py)：构造 PaliGemma 与 gemma_expert，重点读 forward 中两个 inputs_embeds 都不为 None 的分支。
3. [pi0_pytorch.py](../../openpi/src/openpi/models_pytorch/pi0_pytorch.py)：embed_suffix → forward；追踪 noisy_actions、timestep、adarms_cond、suffix_out、v_t。
4. [pi0.py](../../openpi/src/openpi/models/pi0.py)：make_attn_mask、compute_loss。单独看 pistar=True 分支，确认时间权重和普通 MSE 的不同。

做 03、04，补完 02。

在纸上标下面这些形状：

| 位置 | 形状/语义 |
|---|---|
| 状态 | [B,S]，S 来自机器人适配器 |
| 文本 token IDs | [B,L]，L 不是状态维数 |
| 图文 prefix | [B,P,D_vlm] |
| 带噪动作 | [B,H,A_model] |
| 动作 suffix | [B,H,D_expert] |
| 去噪时间 | [B]；RTC 可扩为 [B,H] |
| 时间条件 | [B,D_expert]；RTC 可扩为 [B,H,D_expert] |
| 注意力矩阵 | query token × key token，头维另列 |
| 动作速度 | [B,H,A_model] |

真实两个专家的 D_vlm/D_expert 可以不同。它们分别投影 QKV，进入兼容的 head 空间后拼接序列，attention 后回到各自的输出投影。不要把所有 token 在原始 hidden 维直接拼接当成真实双专家实现。

验收：写出 xτ、uτ 和采样更新式；能解释“时间通过 adaRMS 进入每层”和“动作 chunk 内双向、prefix 不看动作”的原因。

## 第三天：采样闭环 + 后训练梯度

约 1.5—2 小时代码、2.5 小时练习、半小时限时重写。

1. [pi0_pytorch.py](../../openpi/src/openpi/models_pytorch/pi0_pytorch.py) 的 sample_actions：prefix 的 KV cache、suffix 循环、负的 dt。
2. [gemma_pytorch.py](../../openpi/src/openpi/models_pytorch/gemma_pytorch.py) 的 prefix-only 与 suffix-only 分支，与训练时的联合分支对应起来。
3. [policy.py](../../openpi/src/openpi/policies/policy.py)、[policy_config.py](../../openpi/src/openpi/policies/policy_config.py)：输入变换、调用模型、输出逆变换。输出如何回到机器人原始动作维与物理单位？
4. [scripts/train.py](../../openpi/scripts/train.py) 的 train_step：loss、可训练参数集合、梯度、优化器更新。观察冻结策略，避免把 model.eval/no_grad/requires_grad 混在一起。

做 05、06。动作专家题只运行小模型，完整预训练权重无需下载。

限时重写：20 分钟写 Attention 主体；10 分钟写 Flow Matching 构造与 Euler。写不出时标出具体卡点，例如“拆头”“softmax维度”“tau广播”，第二次只针对卡点复练。

验收：小动作专家能接通一次 loss/backward；冻结主干后上游 adapter 仍有梯度；能解释缓存为什么可复用、采样为什么通常不开反向图。

把答案控制在“先说主线，追问再展开”。对源码中实际没用到的路径，不要用通用架构知识替代项目事实。

## 每次读代码固定做四件事

1. 找调用方：这个函数在哪个训练/推理阶段执行？
2. 写形状：B、token 数、特征维分别在哪？
3. 追梯度与 mask：什么参数训练，什么位置允许看见什么？
4. 改一个条件想结果：pi05=False、pistar=False、某相机无效、delay=0，会走哪条分支？

遇到看不懂的代码，记录“文件 + 函数 + 一行问题”，不要抄整页。示例：“embed_suffix 中 state 传入但 pi05=True 时不用，状态来自哪里？”答案应能回到 tokenizer 的实际数据路径。
